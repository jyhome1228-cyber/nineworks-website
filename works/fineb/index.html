01 — PROJECT OVERVIEW

패키지 제작 산업의 정보를 하나의 디지털 접점으로 조직하다.

FINE.B는 단상자, 골판지, 싸바리, 쇼핑백과 같은 다양한 패키지 제작 수요에 대응하는 서비스입니다. 제작을 요청하는 과정에서는 구조와 규격뿐 아니라 용지, 인쇄 방식, 후가공, 수량에 이르기까지 많은 조건을 확인해야 합니다. 이러한 정보를 단순한 서비스 소개에 머무르게 하지 않고, 이용자가 필요한 제작 방식을 이해한 뒤 구체적인 상담과 견적 요청으로 이어지도록 웹사이트의 역할을 확장했습니다. 나인웍스의 작업은 제작 정보를 구조화한 기업 웹사이트와 견적·소량 샘플 신청 경험을 중심으로 전개되었으며, 정보 전달과 실질적인 서비스 이용이 자연스럽게 연결되는 환경을 구축하는 데 초점을 두었습니다.

02 — RESEARCH & PLANNING

제작 조건의 복잡성을 이용자가 이해할 수 있는 선택 과정으로 전환하다.

패키지 제작은 제품 형태마다 적용 가능한 재료와 공정이 다르고, 같은 박스라도 수량이나 규격에 따라 검토해야 할 조건이 달라집니다. 따라서 모든 항목을 한 화면에 나열하기보다 이용자가 자신의 제작 목적을 먼저 파악하고 그다음 필요한 조건을 선택하도록 안내하는 방식이 중요했습니다. 파인비 사이트는 제작 품목과 제작 과정, 가이드, 견적 요청, 소량 샘플이라는 서로 다른 이용 목적을 구별할 수 있도록 구성했습니다. 이 단계에서는 복잡한 제조 관련 정보가 고객의 의사결정을 방해하지 않도록 정보의 순서와 설명 깊이를 조절하고, 상담 전 단계에서 이용자가 스스로 준비할 수 있는 정보를 명확히 제공하는 데 중점을 두었습니다.

03 — INFORMATION ARCHITECTURE

이용 목적에 맞춰 탐색에서 신청까지 이어지는 정보구조.

서비스의 구조는 회사 소개, 제작 품목, 제작 과정, 포트폴리오, 주문제작 가이드, 자주 묻는 질문, 문의, 견적 기능 등으로 구분됩니다. 이용자는 우선 어떤 제작이 가능한지 살펴본 다음 제작 공정과 조건을 이해하고, 자신의 상황에 맞는 견적 또는 샘플 요청으로 이동할 수 있습니다. 상세 페이지는 기능별로 독립시키되 상단 내비게이션을 통해 주요 경로가 유지되도록 구성했으며, 일반 제작 상담과 소량 샘플 제작 신청을 분리해 목적에 따른 혼선을 줄였습니다. 이 정보구조는 서비스 소개 페이지들이 각각 고립되지 않고 제작 검토와 실제 문의라는 공통 목표를 향해 연결되도록 하는 데 의미가 있습니다.

04 — UI DESIGN SYSTEM

다양한 제작 사양을 읽기 쉽고 선택하기 쉬운 화면으로 정리하다.

웹사이트의 인터페이스는 브랜드가 가진 네이비 계열의 시각 언어를 바탕으로 정보 구획과 주요 행동을 구분하도록 구성했습니다. 견적 화면에서는 제작 형태를 고르는 카드, 용지 및 평량을 선택하는 선택 요소, 인쇄와 후가공 옵션을 고르는 입력 영역 등이 각기 다른 정보를 전달하면서도 공통된 UI 규칙을 따릅니다. 진행 단계와 현재 선택된 항목은 상태 변화로 구분하고, 주요 제출 버튼은 일반 탐색 링크보다 높은 시각적 우선순위를 갖도록 설계했습니다. 제작 정보의 분량이 많은 화면인 만큼 타이포그래피의 위계, 항목 간 여백, 선택 상태의 명확성을 확보해 사용자가 현재 무엇을 확인하고 결정해야 하는지 파악할 수 있도록 했습니다.

05 — USER EXPERIENCE

제작 사양을 단계적으로 완성하는 인터랙티브 견적 프로세스.

파인비의 견적 요청 화면은 박스 형태, 종이 선택, 인쇄, 코팅 및 후가공, 최종 견적 요청이라는 다섯 단계로 이루어져 있습니다. 먼저 제작할 박스와 수량, 가로·폭·높이를 선택하고 소재와 평량을 확인한 다음 인쇄 방식, 색상, 인쇄면 및 마감 조건을 지정할 수 있습니다. 각 단계는 입력값을 확인한 뒤 다음 단계로 이동하도록 구현되어 있으며, 선택한 제작 사양을 별도의 요약 영역에서 확인할 수 있습니다. 소량 샘플 신청은 별도로 구성하여 1·2·3·5·10·20개 수량 선택과 샘플용 제작 조건을 지원합니다. 사용자는 두 경로 중 자신의 실제 제작 목적에 적합한 흐름을 선택할 수 있습니다.

06 — RESPONSIVE EXPERIENCE

복잡한 제작 입력 화면을 서로 다른 화면 크기에서 유지하다.

기업 소개 페이지와 별개로 견적 시스템에는 다수의 선택 카드, 제작 사양 요약, 단계별 이동 버튼, 텍스트 입력 필드가 동시에 등장합니다. 이러한 요소는 넓은 데스크톱 화면에서 효율적으로 배치할 수 있지만 화면 폭이 좁아지면 각 정보의 우선순위를 다시 정리해야 합니다. 파인비의 프론트엔드 스타일은 화면 크기에 따라 그리드와 입력 요소의 배치를 변경하는 반응형 규칙을 포함하며, 공통 헤더와 선택형 UI 역시 다양한 사용 환경을 고려해 구성되어 있습니다. 포트폴리오에서는 실제 PC와 모바일 화면을 나란히 비교해 정보의 밀도와 사용 흐름이 어떻게 달라지는지 보여주고, 주요 폼을 중심으로 화면별 가독성을 설명합니다.

07 — FRONTEND DEVELOPMENT

입력 상태와 선택 조건을 연결하는 프론트엔드 로직.

견적 기능은 자바스크립트 기반의 상태 객체를 활용해 현재 단계, 박스 유형, 수량, 치수, 종이, 인쇄 조건, 후가공 선택 등을 관리하도록 구현되어 있습니다. 이용자가 항목을 고르면 관련 선택 카드와 요약 정보가 갱신되며, 종이 선택에 따라 이용 가능한 평량 목록을 표시하는 등 데이터 사이의 관계가 인터페이스에 반영됩니다. 단계 이동 과정에서는 필수 선택 여부와 입력 내용을 검사하고, 요구 조건이 충족되지 않으면 다음 단계로 넘어가지 않도록 처리합니다. 이는 여러 입력 화면을 단순히 연결하는 것보다 복합적인 제작 사양을 하나의 일관된 상태로 관리해야 하는 개발 과제입니다. 실제 코드에서는 사용자 선택, 화면 렌더링, 단계 전환, 최종 요청 데이터 생성이 연결되는 구조를 확인할 수 있습니다.

CLIENT INTERACTION
사용자 선택 → 상태 갱신 → 입력값 검증 → 단계 이동 → 사양 요약

08 — SYSTEM ARCHITECTURE

브라우저에서 구성한 제작 사양을 실제 요청 데이터로 연결하다.

최종 견적 요청 시 서비스는 선택한 제작품목, 수량, 규격, 용지, 평량, 인쇄 방식, 코팅과 후가공 정보에 회사명, 담당자, 연락처, 이메일, 요청사항을 결합해 하나의 요청 데이터로 구성합니다. 제출 과정에서는 담당자 필수 정보와 개인정보 수집 동의 여부를 확인하고, 클라이언트 모듈을 통해 Firebase Firestore에 요청을 저장하도록 연결되어 있습니다. 저장 과정에 문제가 발생할 경우 브라우저에 임시 저장하고 사용자에게 안내하는 예외 처리도 코드에 포함되어 있습니다. 별도의 소량 샘플 및 일반 문의 데이터는 요청 유형에 따라 구분되며, 관리자용 조회·상태 변경 함수도 구현되어 있습니다. 이는 입력 UI부터 데이터 저장과 업무 처리까지 이어지는 기본적인 서비스 운영 구조를 보여줍니다.

REQUEST DATA FLOW
사용자 입력 → 필수 정보 확인 → 요청 데이터 구성 → Firestore 저장 → 관리자 조회 및 상태 관리
근거: quote-app.js · firebase-client.js
09 — TECHNICAL IMPLEMENTATION

웹사이트 구축 이후의 요청 관리와 운영을 고려한 기술 구성.

파인비 웹사이트는 HTML, CSS, JavaScript로 구성된 페이지들과 공통 스타일 및 기능별 스크립트를 중심으로 구축되었습니다. 견적과 샘플 신청 로직은 각각의 자바스크립트 모듈로 구분하고, 제작에 필요한 용지 데이터는 여러 신청 흐름에서 재사용할 수 있도록 별도의 데이터 파일로 관리합니다. Firebase 모듈은 Firestore를 활용한 견적·샘플·문의 저장과 관리자 요청 조회 및 상태 변경 기능을 제공하며, 포트폴리오 이미지 업로드에는 Firebase Storage를 활용하는 코드도 포함되어 있습니다. 방문 데이터 기록과 집계 관련 함수 또한 확인되지만 실제 운영 성과 수치는 별도 검증 없이 제시하지 않습니다. 이 섹션에서는 구축된 기술 구조와 유지보수 관점을 구분해, 화면 디자인뿐 아니라 실제 서비스를 운영할 수 있도록 구성된 개발 범위를 보여줍니다.
